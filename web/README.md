# Fabrary web

Requester counter at `/`; access-code-protected owner workshop at `/owner`.

From this folder:

```sh
npm ci
npm run dev
```

The development server binds only to `127.0.0.1:4317` and proxies `/api` and `/assets` to the backend on `127.0.0.1:4318`. `npm run build` produces the frontend served by the backend. Fonts are bundled locally. Dependencies are exact-pinned with a lockfile.

```sh
npm run typecheck
npm run build
npm run test:unit
npx playwright install chromium
npm run test:browser
npm audit --audit-level=moderate
```

The overnight quality suite additionally covers automated WCAG A/AA rules,
320/390/768/1440 px reflow, keyboard tabs and skip navigation, preview retry,
failed uploads, expired owner sessions, delayed receipt responses, and owner
queue search/filter/pagination. Automated accessibility results complement
the recorded keyboard and visual checks; they do not establish complete
accessibility conformance.

Run the same suite against a built local application and additional engines:

```sh
npx playwright install firefox webkit
FABRARY_BROWSER_URL=http://127.0.0.1:4318 npm run test:browser
FABRARY_BROWSER_ENGINE=firefox FABRARY_BROWSER_URL=http://127.0.0.1:4318 FABRARY_BROWSER_REPORT=evidence/overnight-firefox-browser.json npm run test:browser
FABRARY_BROWSER_ENGINE=webkit FABRARY_BROWSER_URL=http://127.0.0.1:4318 FABRARY_BROWSER_REPORT=evidence/overnight-webkit-browser.json npm run test:browser
```

On macOS, WebKit uses Option+Tab for full keyboard navigation by default. The
keyboard checks exercise that native shortcut without changing system or
browser preferences. UI fixture tests intercept all application requests;
actual workflow tests use local simulation/mock services and the authoritative
database. Each engine's result is recorded separately.

Browser acceptance requires the running application and node, simulation devices, mock payments, and local `.data/local-credentials.json` generated by setup. It opens isolated requester and owner sessions and changes simulated workshop records. It reads the owner code locally without printing it. `FABRARY_OWNER_CODE` can override that source; `FABRARY_BROWSER_URL` can override the default Vite URL. Tracing is disabled to avoid recording authentication request bodies.

The first two browser workflows exercise the actual API, persistence, image preparation, execution node, verification, hold/release/refund records and pickup. The first registers and calibrates the simulated sticker device, completes an order, prepares it, resumes the machine before collection, cancels/refunds a second paid order, then redeems the original pickup and opens its receipt. It checks a 390 px viewport, visible keyboard skip-link focus and page errors. The second exercises unsupported 3D configuration, invalid dimensions, specification invalidation, owner artwork-permission review, budget mandate, expired-quote presentation and offline/reconnect. A third bounded test disables the dashboard and health polling intervals, mutates machine pause/resume from an independent owner API context, and asserts visible changes plus new EventSource refresh events in the open owner page. This verifies the authoritative SpacetimeDB-to-backend-to-SSE-to-UI path independently of polling. Only the browser date is advanced for the expiry rendering assertion; backend expiry and reservation races require their independent integration tests.

Screenshots and a structured browser report are retained in [`evidence/`](evidence/), outside Playwright's cleaned temporary output. These are software acceptance results with explicit simulation/mock labels. They establish no physical output, real wallet connection, testnet transfer, consumable cost, customer evidence or hardware timing target.

Testnet checkout uses an injected EIP1193 browser wallet and the official x402 v2 exact EVM client. The requester explicitly starts checkout, must already select Base Sepolia, and signs an authorization for the approved quote. The client verifies the test network, USDC asset, exact amount, job/quote reference and authorization window, then retries the same checkout with the standard payment-signature header. No private keys are accepted in the interface. Pending settlement remains pending. Eight unit tests use an offline deterministic wallet fixture and a fake EIP1193/fetch boundary; a real wallet and live settlement remain unverified until externally configured acceptance is run.

Hardware calibration has an owner-only upload/start/status/inspection flow and an explicit uncertain-outcome resolution action. It reuses a durable attempt key, shows recorded evidence when available, and does not automatically rerun uncertain jobs. The hardware branch is blocked until a configured paired device and usable camera are supplied; the browser acceptance suite does not operate physical devices.

Prepared 3D orders use only the configured inspected catalog. The production artifact hash binds the actual prepared file; its separate owner-inspected PNG is displayed as a preview. With no catalog, the UI explains the missing prerequisite and disables ordering. Photo-to-3D and unfamiliar-machine onboarding remain planned.

The x402 integration follows the [official core client](https://github.com/x402-foundation/x402/blob/main/typescript/packages/core/README.md) and [EVM mechanism](https://github.com/x402-foundation/x402/blob/main/typescript/packages/mechanisms/evm/README.md) interfaces. The development server uses the patched [Vite 7.3.7 release](https://github.com/vitejs/vite/releases/tag/v7.3.7).

Owner recovery includes a form for an existing pending testnet operation with a durable receipt. It requires the observed transaction hash and a specific reason, calls the server to validate the exact expected confirmed transfer, and never submits a replacement payment. Produced or failed trials can record measured consumable/API/machine costs, time and failed attempts. Fields start blank rather than treating missing measurements as zero. Server-returned allocations are displayed separately from payment state; simulation records are explicitly labeled.

Requester image intake exposes `Suggest specification` after artwork and intent are entered. The connected draft fills only supplied proposal values, preserves manual values when proposals are null, bundles clarification questions, and never approves a file or invents artwork permission. A content review flag can require owner review; a clear flag does not override the requester’s unresolved permission. A missing suggestion service leaves manual entry usable. Prepared 3D catalog selections bind fixed overall width/height/depth, single color, material and estimated machine time; those facts are visible in selection, production preview and approval. There is no fabricated or resized prepared model.

Two additional browser interface fixture tests intercept every API request to check pending-payment reference failure/success presentation, exact measurement submission, suggestion/null-field behavior, permission preservation and unavailable-service fallback. Their separate `evidence/owner-records-ui-report.json` is an interface result, not live settlement, Claude service, hardware or authoritative-store evidence.
